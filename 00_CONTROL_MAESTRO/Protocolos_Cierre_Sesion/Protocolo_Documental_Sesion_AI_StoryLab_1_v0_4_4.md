## 0. Propósito

Este protocolo define cómo cerrar sesiones de trabajo en AI StoryLab 1 de forma coherente, robusta, sostenible, organizada para humanos, histórica y trazable.

---

## 1. Principio rector

```text
Cada sesión debe dejar suficiente memoria para que el proyecto pueda continuar sin perder decisiones, deuda, rutas, contexto, límites ni intención creativa.
```

---

## 2. Niveles de sesión

| Nivel | Uso | Documentación mínima |
|---|---|---|
| Ligera | Conversación exploratoria sin decisión mayor | Nota breve o bitácora mínima |
| Operativa | Producción de documentos o tareas puntuales | Bitácora de sesión + deuda si aplica |
| Estructural | Cambios de cartapacios, rutas, README, mapas | Bitácora + decisión + deuda + transferencia |
| Constitucional | SDD, gates, políticas, privacidad, IA, arquitectura | Paquete completo |
| Cierre de versión | Fin de ciclo o versión | Paquete completo + prompt de continuidad |

---

## 3. Paquete mínimo contextualizado

Para sesiones significativas:

```text
1. Bitácora de sesión.
2. Bitácora de transferencia simétrica.
3. Registro de deuda actualizado.
4. Prompt de continuidad.
5. Bitácora del Capitán cuando haya hito, tensión, decisión estratégica o cambio de rumbo.
```

---

## 4. Bitácora de sesión

Debe registrar:

```text
fecha,
versión,
rama o PR,
objetivo,
acciones realizadas,
documentos creados,
decisiones tomadas,
deuda generada o pagada,
riesgos,
próximo paso.
```

---

## 5. Transferencia simétrica

Debe registrar impacto en:

```text
PH,
IT,
AT,
perfiles de usuario,
cartapacios,
SDD,
investigación,
wiki,
mantenimiento.
```

---

## 6. Bitácora del Capitán

Se actualiza como crónica viva cuando ocurre:

```text
cambio de dirección,
decisión estructural,
cierre de versión,
tensión importante,
hito documental,
decisión sobre IA,
decisión sobre v1.0.0.
```

---

## 7. Opciones para el usuario

Al cerrar sesión, se debe poder escoger:

```text
A. cierre mínimo;
B. cierre operativo;
C. cierre estructural;
D. cierre completo de versión;
E. solo prompt de continuidad.
```

---

## 8. Regla de proporcionalidad

No toda sesión requiere paquete completo. Pero toda sesión significativa debe dejar rastro suficiente para no depender de memoria conversacional invisible.
