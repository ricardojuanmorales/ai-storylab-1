## 1. Propósito

Este documento establece una guía inicial de lenguaje situado para los perfiles humanos considerados en AI StoryLab 1 durante la fase **v0.4.7 Diseño de Experiencia No Funcional**.

Su propósito no es escribir copy final de producto, ni definir pantallas, ni crear onboarding real. Su función es ofrecer criterios documentales para imaginar cómo el proyecto podría hablar de manera clara, cuidadosa, reversible y no extractiva antes de cualquier diseño funcional futuro.

```text
proposito:
  crear_guia_documental_de_lenguaje
  diferenciar_perfiles_humanos
  proteger_agencia_pausa_y_retiro
  evitar_lenguaje_coercitivo
  evitar_vigilancia_o_extraccion
  mantener_microcopy_como_ficticia_y_revisable
```

## 3. Principio rector de lenguaje situado

El lenguaje de AI StoryLab 1 debe funcionar como un puente habitable, no como una orden.

Debe permitir que una persona pueda:

```text
[ ] entender qué se le propone;
[ ] reconocer si desea participar;
[ ] pausar sin castigo;
[ ] retirar o revisar una decisión;
[ ] distinguir ficción de uso real;
[ ] saber cuándo algo toca evidencia, reflexión o visibilidad;
[ ] pedir revisión humana;
[ ] no sentirse reducida a dato, métrica o desempeño.
```

El lenguaje situado no busca controlar la experiencia. Busca hacer visible el umbral.

---

## 4. Pregunta triangular aplicada al lenguaje

Cada fragmento de lenguaje ficticio debe revisarse con la pregunta triangular:

```text
Consentimiento:
  ¿La persona entiende, acepta, puede pausar y puede retirar?

Datos/privacidad:
  ¿Qué dato, evidencia, reflexión, metadato o visibilidad toca?

Seguridad local-first:
  ¿En qué zona ocurre, qué amenaza conceptual activa y qué control humano requiere?
```

Si una frase no puede responder esta pregunta, debe revisarse, reescribirse o registrarse como deuda.

## 5. Perfiles humanos considerados

Esta guía trabaja cuatro perfiles de referencia:

```text
estudiante_escuela_superior
estudiante_universitario
docente
investigador
```

Estos perfiles son categorías documentales, no usuarios reales ni sujetos de prueba.

No deben tratarse como:

```text
dato
usuario_generico
fuente_de_evidencia
productor_de_metricas
sujeto_de_investigacion
objeto_de_vigilancia
```

## 6. Principios generales de tono

El lenguaje debe ser:

```text
claro:
  evita ambiguedad en consentimiento, pausa, retiro y visibilidad.

situado:
  reconoce edad, contexto, rol, madurez y responsabilidad.

reversible:
  recuerda que aceptar no elimina la posibilidad de pausar o retirar.

no_extractivo:
  no sugiere que toda creación debe convertirse en evidencia.

no_vigilante:
  evita frases que impliquen monitoreo, rastreo o juicio constante.

no_punitivo:
  no castiga la duda, el silencio, la pausa o la retirada.

expresivo:
  permite juego, imaginación, ensayo, error y exploración.

humano:
  conserva la posibilidad de revisión, conversación y desacuerdo.
```

## 7. Lenguaje prohibido como tono rector

En v0.4.7 debe evitarse lenguaje que suene a:

```text
obligacion:
  - debes completar
  - tienes que entregar
  - no puedes continuar si no aceptas

vigilancia:
  - estamos monitoreando tu progreso
  - analizaremos tu comportamiento
  - el sistema detectara automaticamente

extraccion:
  - sube tu evidencia real
  - guarda tu reflexion personal
  - comparte tus datos para mejorar la experiencia

evaluacion_automatica:
  - tu creatividad sera puntuada
  - la IA evaluara tu proceso
  - se calculara tu desempeño

promesa_tecnica_no_autorizada:
  - tus datos estan cifrados
  - se almacenara localmente de forma segura
  - puedes exportar tu portafolio

prototipo_encubierto:
  - haz clic aqui
  - completa este formulario
  - presiona guardar
  - inicia sesion
```

Estas frases pueden aparecer solo como ejemplos de riesgo, no como lenguaje recomendado.

## 8. Vocabulario preferido

### 8.1 Para invitación

Usar lenguaje de apertura:

```text
puedes explorar
puedes imaginar
puedes revisar
puedes pausar
puedes decidir
puedes volver mas tarde
puedes dejarlo fuera
```

Evitar lenguaje de presión:

```text
debes completar
tienes que continuar
no puedes avanzar
se requiere participar
```

---

### 8.2 Para consentimiento

Usar lenguaje que haga visible la decisión:

```text
antes de continuar, revisa que entiendes que esto es un ejemplo ficticio
puedes aceptar revisar este escenario o detenerte aqui
esta decision puede pausarse o retirarse en una revision posterior
```

Evitar consentimiento opaco:

```text
al continuar aceptas todo
aceptar es obligatorio
esta accion no puede revertirse
```

---

### 8.3 Para pausa

Usar lenguaje que normalice detenerse:

```text
puedes pausar esta exploracion
puedes detener la revision sin perder agencia
puedes volver a este punto despues
```

Evitar pausa punitiva:

```text
si pausas, perderas progreso
pausar afectara tu resultado
solo puedes pausar una vez
```

---

### 8.4 Para retiro

Usar lenguaje que reconozca retirada legítima:

```text
puedes retirar este elemento del escenario ficticio
puedes decidir que esta reflexion no forme parte del portafolio conceptual
puedes dejar esta evidencia ficticia fuera de revision
```

Evitar retiro condicionado:

```text
no puedes retirar despues de aceptar
retirar requiere justificacion
retirar afectara tu evaluacion
```

---

### 8.5 Para evidencia

Usar lenguaje conceptual:

```text
evidencia ficticia
pieza de exploracion
rastro conceptual
fragmento revisable
elemento candidato
```

Evitar lenguaje real o técnico:

```text
archivo guardado
dato capturado
registro almacenado
evidencia oficial
entrega final
```

---

### 8.6 Para portafolio

Usar lenguaje no definitivo:

```text
portafolio conceptual
coleccion ficticia
seleccion revisable
conjunto narrativo provisional
```

Evitar lenguaje de producto o evaluación:

```text
portafolio final
expediente del estudiante
repositorio evaluativo
archivo oficial
```

---

### 8.7 Para visibilidad

Usar lenguaje prudente:

```text
visibilidad conceptual
audiencia ficticia
revision humana imaginada
contexto de lectura posible
```

Evitar lenguaje de publicación:

```text
publicar
compartir en linea
hacer visible a todos
enviar automaticamente
```

---

### 8.8 Para revisión humana

Usar lenguaje de cuidado:

```text
puedes pedir una revision humana
una persona puede ayudarte a interpretar este escenario
la revision puede detenerse si algo no esta claro
```

Evitar delegación total a sistemas:

```text
la IA decidira
el sistema evaluara
la respuesta sera validada automaticamente
```

## 9. Perfil: estudiante de escuela superior

### 9.1 Enfoque de lenguaje

El lenguaje para estudiantes de escuela superior debe ser especialmente claro, no intimidante y explícito sobre la diferencia entre exploración ficticia y participación real.

Debe reconocer que este perfil puede necesitar:

```text
[ ] instrucciones sencillas;
[ ] confirmación de que puede pausar;
[ ] explicación breve de por qué algo importa;
[ ] lenguaje que no suene a examen;
[ ] protección contra exposición innecesaria;
[ ] acompañamiento adulto o docente en fase futura, si alguna vez se autoriza.
```

En v0.4.7 no se trabaja con estudiantes reales. Este perfil es documental.

### 9.2 Lenguaje recomendado

```text
Puedes mirar este ejemplo ficticio y decidir si quieres seguir revisandolo.
Esta pieza no es una entrega real.
Puedes pausar aqui.
Puedes decir que esta idea no debe formar parte del portafolio conceptual.
Antes de seguir, revisa si entiendes que este escenario es inventado.
```

### 9.3 Lenguaje a evitar

```text
Tu respuesta sera evaluada.
Sube tu evidencia.
Comparte tu reflexion personal.
Continua para completar tu progreso.
El sistema revisara tu desempeño.
```

### 9.4 Riesgo principal

```text
riesgo:
  convertir_exploracion_creativa_en_tarea_obligatoria

mitigacion_documental:
  declarar_ficcion
  permitir_pausa
  evitar_evaluacion
  evitar_datos_reales
  usar_lenguaje_breve_y_revisable
```

## 10. Perfil: estudiante universitario

### 10.1 Enfoque de lenguaje

El lenguaje para estudiantes universitarios puede asumir mayor autonomía, pero no debe convertir esa autonomía en obligación de revelar, producir o entregar.

Debe permitir:

```text
[ ] reflexión crítica;
[ ] negociación de visibilidad;
[ ] revisión de evidencia conceptual;
[ ] pausa sin penalización;
[ ] distinción entre proceso creativo y desempeño académico;
[ ] rechazo de interpretación automática.
```

### 10.2 Lenguaje recomendado

```text
Puedes revisar esta evidencia ficticia como parte de una exploracion conceptual.
Puedes decidir si este fragmento pertenece o no al portafolio conceptual.
Puedes pausar la interpretacion antes de aceptar una lectura.
Puedes pedir revision humana si el encuadre no representa tu intencion.
```

### 10.3 Lenguaje a evitar

```text
Esta reflexion se usara para analizar tu proceso.
El sistema identificara patrones en tu creatividad.
Tu portafolio sera compartido automaticamente.
Acepta para continuar con la actividad.
```

### 10.4 Riesgo principal

```text
riesgo:
  convertir_autonomia_universitaria_en_extraccion_de_reflexion

mitigacion_documental:
  enfatizar_decision
  permitir_retiro
  evitar_analiticas
  evitar_interpretacion_automatica
  registrar_deuda_si_hay_tension_academica
```

## 11. Perfil: docente

### 11.1 Enfoque de lenguaje

El lenguaje para docentes debe reconocer responsabilidad pedagógica sin convertir al docente en operador de vigilancia o extracción de evidencia.

Debe ayudar a:

```text
[ ] explicar límites a estudiantes;
[ ] distinguir acompañamiento de evaluación;
[ ] sostener revisión humana;
[ ] evitar uso coercitivo de escenarios;
[ ] identificar deuda antes de activar prácticas reales;
[ ] mantener ética local-first como criterio pedagógico.
```

### 11.2 Lenguaje recomendado

```text
Este escenario ficticio puede servir para revisar riesgos antes de cualquier uso real.
La persona participante conserva pausa, retiro y revision.
No convierta esta microcopy en instruccion de aula.
Revise si la evidencia conceptual podria confundirse con entrega real.
```

### 11.3 Lenguaje a evitar

```text
Use este flujo con sus estudiantes.
Recoja las respuestas del grupo.
Evalúe automaticamente los portafolios.
Solicite reflexiones personales para alimentar el sistema.
```

### 11.4 Riesgo principal

```text
riesgo:
  convertir_guia_documental_en_actividad_pedagogica_real

mitigacion_documental:
  repetir_no_aplicacion
  marcar_escenarios_como_ficticios
  bloquear_pruebas_con_personas
  transferir_investigacion_a_fase_futura_no_autorizada
```

## 12. Perfil: investigador

### 12.1 Enfoque de lenguaje

El lenguaje para investigadores debe ser preciso sobre límites, evidencia y no activación de investigación.

Debe recordar:

```text
[ ] los escenarios son ficticios;
[ ] no hay sujetos humanos;
[ ] no hay datos reales;
[ ] no hay instrumentos de investigación;
[ ] no hay protocolo IRB o equivalente activado;
[ ] no hay análisis de comportamiento real.
```

### 12.2 Lenguaje recomendado

```text
Este escenario no constituye dato de investigacion.
Esta matriz permite revisar supuestos, no recolectar evidencia.
Cualquier investigacion futura requeriria autorizacion documental separada.
La interpretacion aqui es conceptual y no debe aplicarse a personas reales.
```

### 12.3 Lenguaje a evitar

```text
Recolectar respuestas.
Analizar participantes.
Observar patrones reales.
Validar el modelo con usuarios.
Usar los escenarios como instrumento de estudio.
```

### 12.4 Riesgo principal

```text
riesgo:
  convertir_escenarios_ficticios_en_instrumentos_de_investigacion

mitigacion_documental:
  declarar_no_investigacion
  bloquear_datos_reales
  registrar_deuda_futura
  exigir_gate_especifico_si_se_propone_investigacion
```

## 15. Plantillas ficticias revisables

Las siguientes plantillas son ejemplos ficticios. No son copy final ni instrucciones de uso real.

### 15.1 Invitación ficticia general

```text
Este es un escenario inventado para revisar cómo se podría cuidar la experiencia.
Puedes explorarlo, pausarlo o dejarlo fuera de revisión.
Nada aquí solicita datos reales ni activa una actividad real.
```

### 15.2 Consentimiento ficticio

```text
Antes de continuar la revisión documental, confirma que entiendes tres cosas:
esto es ficticio, puedes pausar y puedes retirar este elemento del análisis.
```

### 15.3 Pausa ficticia

```text
Puedes detenerte aquí.
La pausa no significa abandono.
También puede ser una forma de cuidar la decisión.
```

### 15.4 Retiro ficticio

```text
Puedes retirar esta pieza del portafolio conceptual.
No necesitas justificarlo dentro de este escenario.
```

### 15.5 Evidencia ficticia

```text
Esta pieza se considera evidencia ficticia solo para revisión documental.
No representa una entrega real ni debe asociarse con una persona real.
```

### 15.6 Revisión humana ficticia

```text
Si esta interpretación no representa bien la intención creativa imaginada, puede pasar a revisión humana conceptual.
```

## 16. Criterios de accesibilidad expresiva

El lenguaje situado debe considerar accesibilidad expresiva, no solo claridad instrumental.

Debe permitir:

```text
[ ] leer en fragmentos breves;
[ ] entender sin jerga innecesaria;
[ ] revisar antes de aceptar;
[ ] expresar duda;
[ ] usar distintas formas de creación;
[ ] no responder inmediatamente;
[ ] no convertir silencio en falla;
[ ] no convertir diferencia expresiva en déficit.
```

Debe evitar:

```text
[!] frases largas con doble obligación;
[!] presión de productividad;
[!] metáforas que oculten condiciones;
[!] lenguaje técnico sin definición;
[!] tono de evaluación;
[!] lenguaje que presuponga acceso, velocidad o confianza.
```

## 22. Cierre

Esta guía propone un lenguaje que no empuja a la persona por un pasillo único.

Cada frase debe funcionar como señal de cubierta: indica dónde se puede mirar, dónde se puede pausar, dónde se puede volver y dónde todavía no se debe cruzar.
