## 0. Propósito

Este documento registra las decisiones de alineación tomadas antes y durante PR #9 para estabilizar la estructura documental de AI StoryLab 1 v0.4.4 antes del cierre constitucional definitivo y la apertura de v0.4.5.

Su función es convertir acuerdos conversacionales y criterios de planificación en autoridad documental explícita.

---

## 1. Decisión matriz

AI StoryLab 1 v0.4.4 se cerrará mediante dos movimientos coordinados:

```text
PR #9:
  pago completo de la deuda estructural actual,
  estabilización de cartapacios,
  mapa real,
  tabla de ubicación,
  registro de deuda,
  gate constitucional,
  plantilla README,
  protocolo documental de sesión
  y bitácora del capitán inicial.

PR #10:
  cierre constitucional definitivo v0.4.4,
  consolidación de Constitución SDD,
  sincronización de derivados,
  cierre de documentación activa,
  bitácoras finales,
  puente hacia v0.4.5.
```

---

## 2. Decisión sobre v0.4.5

v0.4.5 queda definida preliminarmente como:

```text
Fase de specs operativas con semillas arquitectónicas.
```

Esto significa:

```text
1. No inicia implementación funcional.
2. No introduce backend, cloud, autenticación, analíticas ni IA externa por defecto.
3. Produce specs operativas completas.
4. Cada spec anticipa objetos, datos, riesgos, pruebas y dependencias arquitectónicas preliminares.
5. La fase mantiene pensamiento puente hacia implementación responsable, sin cruzar todavía a construcción funcional.
```

---

## 3. Decisión sobre camino hacia v1.0.0

AI StoryLab 1 adoptará un modelo combinado:

```text
Secuencia principal flexible + doble eje operativo + gates como autoridad de avance.
```

Esto significa:

```text
1. Las fases mantienen orden lógico:
   SDD → arquitectura → diseño → implementación → testing → validación → despliegue → mantenimiento.

2. Cada versión tiene foco dominante.

3. Cada módulo importante debe declarar su relación con:
   specs,
   arquitectura,
   diseño,
   pruebas,
   validación,
   deuda,
   perfiles,
   investigación
   y documentación.

4. Ninguna fase puede invadir prematuramente la siguiente sin documento de pase, gate y decisión registrada.
```

---

## 4. Decisión sobre v1.0.0

v1.0.0 no se definirá únicamente como app funcional.

v1.0.0 se definirá como:

```text
Ecosistema transdisciplinario responsable.
```

Debe demostrar:

```text
funcionalidad estable,
sistema SDD completo,
arquitectura y diseño coherentes,
local-first,
seguridad y privacidad,
consentimiento informado y situado,
pruebas técnicas,
validación humana,
documentación activa,
wiki humana,
investigación transdisciplinaria,
transferencia PH-IT-AT,
usabilidad para estudiante de escuela superior, estudiante universitario, docente e investigador,
mantenimiento documentado,
deuda estructural cerrada o explícitamente diferida con versión objetivo.
```

---

## 5. Decisión sobre integración humano / máquina / IA

La integración humano / máquina / IA se define como:

```text
Mediación transdisciplinaria responsable.
```

La plataforma y la IA pueden conectar creatividad, reflexión, datos, perfiles, riesgos, investigación, decisiones humanas y documentación.

Pero no pueden operar como autoridad invisible.

---

## 6. Gate para IA responsable

La IA solo puede pasar de asistente a co-creadora situada cuando exista:

```text
spec aprobada,
consentimiento informado y situado,
threat model,
datos permitidos,
revisión humana,
pruebas,
trazabilidad,
reversibilidad,
explicación humana,
no juicio final,
opción clara de no usar IA.
```

---

## 7. Trazabilidad de uso de IA

Cada participación de IA deberá registrar, cuando aplique:

```text
propósito,
perfil,
etapa creativa,
datos tocados,
consentimiento,
límites,
salida generada,
revisión humana,
deuda,
decisión de conservar, editar o descartar.
```

---

## 8. Decisión sobre creatividad y flujo de trabajo

Las fases secuenciales no deben interferir con el proceso creativo.

El flujo se define así:

```text
idea creativa
→ bitácora creativa
→ spec situada
→ arquitectura
→ diseño
→ implementación
→ testing
→ validación
→ despliegue
→ mantenimiento
```

Cada fase debe operar como experiencia creativa, no como formulario rígido.

---

## 9. Decisión sobre documentación de sesión

Se adopta un protocolo documental escalonado con base mínima obligatoria.

Cada cierre de sesión significativa deberá producir o actualizar:

```text
bitácora de sesión,
bitácora de transferencia simétrica,
registro de deuda,
prompt de continuidad,
bitácora del capitán cuando aplique.
```

La Bitácora del Capitán se reconoce como crónica viva longitudinal del proceso.

---

## 10. Decisión sobre excepción `Base_Conocimiento_SDD/`

Se valida como excepción operativa para v0.4.4 la ruta:

```text
05_COMPETENCIAS_Y_PERFILES/Programador_Humanista/Base_Conocimiento_SDD/
```

Condiciones:

```text
1. Opera como base formativa SDD del PH.
2. No reemplaza `Conocimiento_Comun/`.
3. No autoriza rutas paralelas sin decisión registrada.
4. Debe mantener obligación de transferencia PH-IT-AT.
5. Debe revisarse en cierre de v0.4.4 o preparación de v0.5.0.
```

---

## 11. Decisión sobre deuda estructural

La deuda estructural actual de v0.4.4 debe quedar pagada en PR #9 antes de abrir formalmente la fase v0.4.5.

La deuda futura podrá registrarse, pero no debe quedar deuda estructural actual no atendida como herencia de v0.4.4.

---

## 12. Dictamen

Esta decisión autoriza completar PR #9 como paquete de pago estructural completo y preparar PR #10 como cierre constitucional definitivo v0.4.4.

**Dictamen:** Decisión aprobada para incorporación en PR #9.
