---

## 1. Propósito

Este documento establece el Gate de Transición para la fase **v0.4.7 Diseño de Experiencia No Funcional**.

Su función es decidir si la fase puede avanzar hacia cierre documental, continuar revisión o transferir deuda a fases futuras. Este gate no autoriza implementación, prototipo, UI real, investigación, datos reales ni arquitectura técnica ejecutable.

El gate funciona como compuerta: revisa presión, dirección y límites antes de permitir que la documentación pase al tramo final.

---

## 2. Decisión que este gate sí puede tomar

Este gate puede decidir:

```text
[✓] si la documentación v0.4.7 está suficientemente alineada;
[✓] si la deuda documental autorizada fue pagada;
[✓] si la deuda no autorizada quedó bloqueada;
[✓] si los documentos mantienen lenguaje no funcional;
[✓] si la fase puede preparar changelog, transferencia simétrica y cierre;
[✓] si hace falta una ronda adicional de revisión documental.
```

---

## 3. Decisión que este gate no puede tomar

Este gate no puede decidir:

```text
[!] iniciar implementación;
[!] diseñar UI real;
[!] construir prototipo;
[!] activar pruebas con personas;
[!] crear instrumentos de investigación;
[!] trabajar con datos reales;
[!] diseñar arquitectura técnica;
[!] definir permisos, cifrado, retención, sincronización o backend;
[!] convertir microcopy ficticia en copy final;
[!] convertir acciones sensibles en funciones;
[!] convertir escenarios ficticios en actividades.
```

## 5. Pregunta triangular del gate

```text
Consentimiento:
  ¿Todos los documentos preservan comprensión, aceptación, pausa, retiro y revisión humana?

Datos/privacidad:
  ¿Todos los documentos distinguen evidencia ficticia, reflexión conceptual, visibilidad ficticia y datos reales no autorizados?

Seguridad local-first:
  ¿Todos los documentos mantienen amenazas en nivel conceptual y evitan diseño técnico ejecutable?
```

---

## 6. Criterios de pase

El gate puede pasar si se cumplen todos los criterios:

```text
[ ] no hay implementación funcional;
[ ] no hay UI real;
[ ] no hay wireframes;
[ ] no hay prototipo;
[ ] no hay onboarding real;
[ ] no hay actividad aplicable con estudiantes;
[ ] no hay pruebas con personas;
[ ] no hay evaluación automática;
[ ] no hay investigación con datos reales;
[ ] no hay instrumentos de investigación;
[ ] no hay captura, almacenamiento o exportación real de evidencia;
[ ] no hay arquitectura técnica ejecutable;
[ ] microcopy permanece ficticia y revisable;
[ ] escenarios permanecen ficticios;
[ ] acciones sensibles permanecen conceptuales;
[ ] controles habitables no se convierten en permisos técnicos;
[ ] portafolio conceptual no se convierte en expediente;
[ ] deuda futura queda bloqueada o transferida;
[ ] la fase puede preparar changelog y cierre.
```

## 13. Cierre

El gate permite continuar hacia cierre documental, no hacia construcción.

La nave sigue en astillero conceptual. Las cartas están más limpias, las deudas están marcadas y la compuerta solo abre hacia bitácora, changelog y transferencia, no hacia motores funcionales.
